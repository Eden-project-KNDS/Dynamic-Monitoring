Eden Cluster Monitoring

Dynamic Monitoring for Slurm GPU Clusters

  • Problem: users frequently over-request GPUs, CPU, and memory, leaving expensive cluster resources underused.
  • Architecture: node-local Go exporter reads NVIDIA NVML metrics, cgroup v2 job counters, and Slurm metadata, then exposes Prometheus eden_* metrics.
  • Performance: profiling shows most execution time is spent in NVML/driver calls, not in Go application logic; the runtime is lightweight and avoids expensive background loops.
  • Impact: transparent job-level visibility, better right-sizing decisions, and improved cluster utilization for future optimization workflows.
Key design points
NVML + cgroups + Slurm
Prometheus scrapes live metrics from each node, while Grafana visualizes resource usage, job attribution, and inefficiency signals in near real time.
Architecture: exporter → Prometheus → Grafana Performance profile: driver-bound, not Go-bound
